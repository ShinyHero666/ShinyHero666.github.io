PROJECT 01 · BOUNDED DECISION AGENT

BuySense智购决策 Agent

面向 3C 数码与户外露营场景的购物决策多 Agent 系统。角色 Agent 负责意图理解、候选重排、任务交接、审核与解释，Java 服务负责预算、品类、库存、兼容性、广告和交易边界。

01 / PROBLEM

解决什么问题

用户不会只输入标准关键词，真实问法往往同时包含预算、用途、品牌偏好、性能、兼容性和交付要求。传统检索容易漏掉约束，纯 LLM 推荐又可能虚构价格、库存或商品能力。

给程序员配一套桌面设备，别推软广组合推荐 · 办公开发场景品类覆盖、搭配兼容、广告策略
02 / FLOW

有界协作链路

每个 Role Agent 在自己的工具和权限范围内执行“观察上下文、选择工具、读取结果、发布结构化 Artifact”的循环。Intent Agent 解析需求后，Search 与 Ads 并行执行；Search 可向 Recommendation 发起受限任务交接，随后进入融合、组合求解、证据刷新、确定性审核、Critic 复核和 Lead 输出。

03 / CONTROL

模型边界与工程控制

  • Domain Pack 隔离目录、同义词、兼容图、评论切面和业务策略；当前以 3C 为主场景，并用户外露营验证领域扩展边界。
  • Role Agent 可动态选择已授权工具、发布 Artifact 或申请 Handoff；协调器限制任务数、交接深度、并发、模型调用、截止时间和修订次数。
  • 模型负责检索词、软偏好、候选重排和证据表达，不能覆盖预算、品类、库存、兼容性、广告规则或交易权限。
  • Search 与 Recommendation 使用 Weighted RRF 融合；Ads 走独立的相关性、质量、疲劳度、披露和展示位门禁。
  • 兼容图在预算内枚举可行套装，同时满足品类覆盖和搭配约束，避免逐项贪心产生局部最优。
  • Retail Provider SPI 解耦本地快照、HTTP 数据源和只读 Shopify GraphQL；独立 Review Provider 提供带样本量、维度、情感和置信度的评论聚合证据。
  • 异步 Run 采用数据库原子准入、有界执行器、租约续期和 fencing，支持取消、幂等复用、SSE 回放与过期任务恢复。
  • 确定性 Audit 先于 Critic 执行，最多允许一次 Critic 驱动的修订；确认前刷新价格库存，最终只生成 paymentAuthorized=false 的购物车草案。
04 / EVALUATION

可复现工程证据

评测将公开任务与本地隐藏 Gold 分离：12 个能力场景分别重复 3 次，并在确定性无模型基线、去 Critic 版本和完整多 Agent 版本上执行。三个变体使用相同目录快照、模型配置和评分契约，避免通过修改样本或提示词追逐结果。
