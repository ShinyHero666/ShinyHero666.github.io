PROJECT 01 · BOUNDED DECISION AGENT

BuySense智购决策 Agent

以 3C 数码为主业务、户外露营为扩展验证的智能购买决策平台。Java 主控按请求复杂度选择澄清、确定性工作流或 Planner-Critic 混合链路，并通过 Java Provider SPI 原生直连 Shopify Admin GraphQL，让模型负责语义增强，让确定性服务守住预算、库存、广告与兼容性。

01 / PROBLEM

解决什么问题

用户不会只输入标准关键词，真实问法往往同时包含预算、用途、品牌偏好、性能、兼容性和交付要求。传统检索容易漏掉约束，纯 LLM 推荐又可能虚构价格、库存或商品能力。

用户输入系统理解确定性约束
5000 内，拍照好，能和我的 Windows 笔记本协同手机选购 · 预算优先 · 影像偏好价格上限、库存、系统兼容
给程序员配一套桌面设备，别推软广组合推荐 · 办公开发场景品类覆盖、搭配兼容、广告保护
02 / FLOW

自适应决策链路

ExecutionRouter 根据品类数、套装、多目标、模糊表达和信息完整度选择 CLARIFICATION、WORKFLOW 或 HYBRID。两个版本化 Domain Pack 共用 10 项能力与有界委派图；简单请求不调用模型，复杂请求只允许 Planner 增强检索词与软偏好。

需求解析预算、品类、用途与约束强度
领域与路由2 Domain Packs / 10 Capabilities
多路召回Search / Recommendation / Ads
融合与组合Weighted RRF / 全局约束枚举
证据与运行Java Shopify / Critic / Leased Run
03 / CONTROL

模型边界与工程控制

  • 预算、必选品类、广告偏好和兼容性是不可覆盖的硬约束；Query Rewrite 只能补充检索词、用途和软偏好。
  • Search、Recommendation、Ads 通过 Weighted RRF 融合，并在最终排序前执行前三位广告保护和硬过滤。
  • 套装选择采用有界全局枚举，同时满足预算、品类覆盖与兼容性，避免逐项贪心产生局部最优。
  • Critic 只能返回 APPROVE、RETRIEVE 或 CLARIFY；补充检索最多一次，澄清建议还需通过确定性策略门。
  • Catalog、Review、Pricing 通过 Java Provider SPI 解耦；Shopify 实现固定 GraphQL 查询、校验只读 Scope、版本、GID、元数据与报价集合，普通决策缓存目录，确认前强制刷新，fallback 快照不能用于确认。
  • 异步 Run 采用数据库原子准入、有界队列、租约续期与 fencing，支持取消、SSE 回放和过期任务恢复；确认前刷新价格、库存与兼容性，失败可重试，支付始终禁用。
