PROJECT 02 · AI INFRASTRUCTURE

RouteSmith智路网关

基于 Java 17 与 Spring WebFlux 实现的多模型治理网关。统一 OpenAI / Anthropic 协议，并以请求感知路由、延迟 SLO、故障转移、预算账本和幂等复用承接 Agent 应用的模型访问。

01 / PROBLEM

为什么需要网关

当多个 Agent 直接接入不同模型服务时，协议适配、凭证、重试和成本逻辑会散落在业务代码中。模型切换会扩大改动范围，也难以统一追踪一次请求经过了哪个 Provider、花费多少、为何降级。

问题RouteSmith 的处理
OpenAI / Anthropic 请求格式不同协议适配层统一消息、Tool Call、结束原因、Usage 与 SSE
上游限流或服务异常健康状态、熔断、冷却与有限候选故障转移
团队额度难以控制请求级预算预留、真实 Usage 结算和 SQL 用量账本
02 / FLOW

可解释路由链路

业务侧只依赖统一兼容协议。RouteSmith 先抽取输入 / 输出 Token、Tool、流式模式、客户端协议与延迟 SLO，按上下文窗口、Tool 和流式能力硬过滤候选，再结合价格、Prefill / Decode 吞吐、EWMA 延迟和可靠性完成请求级排序。

兼容入口OpenAI Chat / Anthropic Messages
请求治理API Key / 幂等 / 预算预留
请求感知路由能力过滤 / 成本延迟预测 / SLO
Provider 适配Tool Call / SSE / 协议转换
结算与证据SQL Ledger / Health / Route Trace
03 / RELIABILITY

故障与额度边界

  • 先执行上下文窗口、Tool 能力、流式能力与 Provider 健康状态硬过滤，评分不能让不兼容候选重新进入列表。
  • 质量、成本、延迟与均衡策略共享同一请求画像；满足延迟 SLO 的候选优先，全部超限时选择预测最优的 best-effort 结果并留下 Trace。
  • 同协议 SSE 可原生透传并关注首包时间；跨协议转换需要完整聚合后合成事件，因此按完整生成耗时估算。
  • 429、5xx、超时和首包前断连可切换到下一候选；路由计划是有限有序列表，每个候选最多尝试一次。
  • Provider 连续失败达到阈值后打开熔断器；流式响应已经输出内容后不再切换，避免重复或语义不一致的 Token。
  • 同一业务请求只预留一次 Token 预算，跨 Provider fallback 不重复占用；成功按真实 Usage 结算，全部失败时释放。
  • 客户端 API Key 与上游 Provider 凭证隔离；幂等响应缓存与追加式 SQL 用量账本分别约束重复执行和计费追溯。
